Project Overview

A full-stack blogging platform for Hivon Automations internship assignment. It supports three user roles, AI-powered post summaries via Google Gemini, search, pagination, and a full admin panel — all built with Next.js 14 App Router and Supabase.

✦
Every blog post automatically gets a ~200-word AI summary generated by Google Gemini at creation time, stored in the database, and displayed on the listing page — with zero repeated API calls.

Database Schema

Three tables as required. Run supabase-schema.sql in the Supabase SQL Editor.

users

id           UUID PRIMARY KEY  -- references auth.users
name         TEXT NOT NULL
email        TEXT UNIQUE NOT NULL
role         TEXT  -- 'author' | 'viewer' | 'admin'
avatar_url   TEXT
created_at   TIMESTAMPTZ

posts

id           UUID PRIMARY KEY
title        TEXT NOT NULL
body         TEXT NOT NULL
image_url    TEXT             -- featured image
author_id    UUID → users.id
summary      TEXT             -- AI-generated, stored once
slug         TEXT UNIQUE NOT NULL
published    BOOLEAN DEFAULT TRUE
created_at   TIMESTAMPTZ

comments

id            UUID PRIMARY KEY
post_id       UUID → posts.id
user_id       UUID → users.id
comment_text  TEXT NOT NULL
created_at    TIMESTAMPTZ
🔒
All three tables have Row Level Security (RLS) enabled. Policies enforce that users can only read/write data they're permitted to access, with a final security backstop at the database level.

User Roles & Permissions

✍️ Author
Create posts
Edit own posts
Delete own posts
View comments on their posts
Comment on any post
👁 Viewer
View all blog posts
Read AI summaries
Comment on posts
Delete own comments
🛡 Admin
Edit any post
Delete any post
Monitor all comments
Delete any comment
Change user roles
⚠️
Permissions are enforced at 3 layers: UI rendering (buttons hidden), API routes (401/403 responses), and Supabase RLS (database-level). To make yourself an Admin, update your role in the Supabase Dashboard → Table Editor → users table.

Local Development Setup

Step 1 — Clone & install

git clone https://github.com/YOUR_USERNAME/hivon-blog.git
cd hivon-blog
npm install

Step 2 — Set up Supabase

1
Go to supabase.com and create a new project (free tier)
2
Open SQL Editor and paste the entire contents of supabase-schema.sql then click Run
3
Go to Storage → Create bucket named post-images, set to public
4
Go to Project Settings → API and copy your URL and anon key

Step 3 — Get Google AI key

1
Visit aistudio.google.com and sign in with Google
2
Click Get API Key → Create API key in new project
3
Copy the key — free tier includes generous quota for summaries

Step 4 — Configure env & run

cp .env.local.example .env.local
# Fill in your values — see Section 7 below

npm run dev
# Open http://localhost:3000

SUPABASE_SERVICE_ROLE_KEY

NEXT_PUBLIC_APP_URL

⚠️
Never commit .env.local to Git. It's in .gitignore. The service role key bypasses RLS — treat it like a password.

AI Summary Integration

Google Gemini 1.5 Flash is called once per post at creation time. The summary is stored in the database — never regenerated on reads.

1
Author submits new post form with title + HTML body
2
Strip HTML tags from body to get clean text input
3
Truncate to 3,000 chars to reduce input tokens (cost optimization)
4
Send prompt to Gemini 1.5 Flash: "Generate a ~200-word summary of this post"
5
Store summary in posts.summary column — never fetched from AI again
6
Display summary on listing page (preview) and post page (full, in styled box)
💡
Cost optimization: 1000 posts = exactly 1000 Gemini API calls total, regardless of how many billions of times those posts are read. The summary is computed once and cached in PostgreSQL forever.

Deployment to Vercel

Step 1 — Push to GitHub

git init
git add .
git commit -m "feat: Hivon Blog Platform - initial commit"
git remote add origin https://github.com/YOUR_USERNAME/hivon-blog.git
git push -u origin main

Step 2 — Import on Vercel

1
Go to vercel.com → New Project → Import from GitHub
2
Select your hivon-blog repository
3
In Environment Variables, add all 5 variables from Section 7 (use your production Supabase keys)
4
Click Deploy — Vercel auto-detects Next.js, no config needed

Step 3 — Configure Supabase Auth redirect

# In Supabase Dashboard → Authentication → URL Configuration
# Add to "Redirect URLs":
https://your-app.vercel.app/api/auth/callback
✓
After deploy, update NEXT_PUBLIC_APP_URL on Vercel to your actual Vercel domain URL.

Key Application Flows

Authentication Flow

1
User registers at /auth/register selecting Viewer or Author role
2
Supabase Auth creates user → DB trigger auto-creates users row with role
3
Session stored in cookies via auth-helpers-nextjs
4
middleware.ts protects /dashboard/* and /admin/* — redirects if no session

Post Creation Flow (Author)

1
Author goes to /dashboard/posts/new, fills in title, body, optional image URL
2
POST /api/posts — verifies session + role ('author' or 'admin' only)
3
Generates unique slug, calls Gemini API for summary
4
Inserts post row with summary into Supabase, redirects to /blog/[slug]
